# Phase 2B disposable PostgreSQL write-test proposal — approval required

No database has been created or deleted and no PostgreSQL write test has run.
The older `phase2b_isolated_*_proposed.sql` schema-in-restored-DB scripts are
superseded and deliberately abort if executed.

## Fixed boundaries

| Purpose | Host and port | Database | Database role | Schema |
| --- | --- | --- | --- | --- |
| Preserved baseline | `127.0.0.1:55432` | `eggsor_restore_test` | local administrator, read-only transaction | `public` |
| Synthetic write tests | `127.0.0.1:55432` | `eggsor_p2b_disposable` | `eggsor_phase2b_runner` | `eggsor_p2b_test` |

The new database starts from `template0`, never from the restored database.
Creation attaches a fixed database comment that setup and cleanup check as a
marker; an existing database name is always a stop condition.
No historical rows or credentials are copied. The fixture schema contains five
empty Phase 1-compatible tables, three internal foreign keys, four local
`GENERATED BY DEFAULT AS IDENTITY` sequences, primary/unique/check constraints,
and the three relationship indexes. Test users have synthetic names and
unusable password strings. The writer has CRUD on those five tables and use of
their sequences. It cannot create database/schema objects, truncate tables,
alter `public`, or bypass RLS. `public` in the disposable database stays empty.

Application mode `PHASE2B_WRITE_TEST_MODE=1` requires an explicit URL with the
exact host, port, database, role, and password. It ignores `SUPABASE_DB_URL`
and `DATABASE_URL`, skips `.env`, admin bootstrap, backfills, automatic sorting,
camera, and ESP32. On import it first verifies the actual server/database/role,
five model tables, three validated internal foreign keys, four sequences, and
permissions in a read-only transaction. `LIFECYCLE_WRITES_ENABLED` remains false
until the opt-in integration runner completes those checks. SQLAlchemy maps
unqualified model tables to `eggsor_p2b_test` and the connection's search path
is `pg_catalog`, so an unexpected unqualified raw query cannot find fixtures.
The old `LOCAL_TEST_MODE=1` remains read-only and points only to
`eggsor_restore_test`; the two modes cannot be combined.

credential. PostgreSQL prompts for the local administrator password with `-W`.
Stop at the first error and report it; do not rerun creation or cleanup blindly.

```powershell
$psql = 'C:\Program Files\PostgreSQL\18\bin\psql.exe'
$env:PGSSLMODE = 'disable'
$before = Join-Path $env:TEMP 'eggsor_p2b_public_before.txt'
& $psql -X -W -h 127.0.0.1 -p 55432 -U postgres -d eggsor_restore_test -v ON_ERROR_STOP=1 -A -t -q -f supabase/verification/phase2b_restored_baseline_readonly.sql | Set-Content -LiteralPath $before

```

The preflight requires empty fixtures, exactly the expected internal FKs and
sequences, an empty disposable `public`, no elevated runner role flags or
membership, no write permissions outside the fixture schema, and no callable
non-system `SECURITY DEFINER` routine. The Python startup repeats its key checks
before the first write. Run only the opt-in module in a fresh Python process:

```powershell
$env:PHASE2B_RUN_POSTGRES_WRITE_TESTS = 'I_APPROVE_DISPOSABLE_WRITES'
try {
    .\.venv\Scripts\python.exe -m unittest -v test_phase2b_postgres
    if ($LASTEXITCODE -ne 0) { throw 'Phase 2B PostgreSQL tests failed' }
} finally {
    Remove-Item Env:PHASE2B_RUN_POSTGRES_WRITE_TESTS -ErrorAction SilentlyContinue
}
```

Python prompts privately for the runner password and builds the dedicated URL
only in the test process. The module skips itself without the exact opt-in flag.
Its synthetic records remain in the disposable database for inspection. Tests
cover parent commit before mocked component startup, authenticated ownership,
concurrent starts, login/logout audit ownership, egg/audit atomic persistence
and deduplication, delayed old
session rejection, normal stop, failed startup, rejected FK insert rollback,
restart reconciliation, and deletion rules. No camera, serial port, model
weights, servo, or firmware are used.

After tests, run the disposable postflight and the preserved baseline again:

```powershell
& $psql -X -W -h 127.0.0.1 -p 55432 -U eggsor_phase2b_runner -d eggsor_p2b_disposable -v ON_ERROR_STOP=1 -f supabase/verification/phase2b_disposable_postflight_readonly.sql
if ($LASTEXITCODE -ne 0) { throw 'Disposable postflight failed' }

& $psql -X -W -h 127.0.0.1 -p 55432 -U postgres -d eggsor_restore_test -v ON_ERROR_STOP=1 -A -t -q -f supabase/verification/phase2b_restored_baseline_readonly.sql | Set-Content -LiteralPath $after
if ($LASTEXITCODE -ne 0) { throw 'Restored baseline postflight failed' }
if ((Get-Content -LiteralPath $before -Raw) -cne (Get-Content -LiteralPath $after -Raw)) { throw 'Restored baseline changed; stop and investigate' }
Remove-Item Env:PGOPTIONS -ErrorAction SilentlyContinue
Remove-Item Env:PGSSLMODE -ErrorAction SilentlyContinue
```

Review the test results and disposable objects before cleanup. Cleanup is a
separate approval: run `phase2b_disposable_cleanup_proposed.sql` as local
`postgres` while connected to the maintenance database `postgres`. It checks
the exact target, owner, marker, and active sessions. It uses neither `FORCE`
nor `CASCADE`; `DROP DATABASE` itself cannot be in a transaction. If the
following `DROP ROLE` fails, report the remaining role instead of retrying.
The restored database is never a cleanup target.

## Limits

The disposable database is on the same local PostgreSQL cluster as the
restored database. Its separate database boundary and fixed runtime guards
are stronger than a schema inside the restored database. The cluster
administrator used for setup still has broad rights; run only the reviewed
scripts with the exact connection arguments. A second local cluster would
provide a further physical boundary but is unnecessary for these tests.

RLS is enabled on the restored Phase 1 tables. The disposable fixtures leave
RLS disabled so the restricted role can exercise lifecycle CRUD; these tests
do not verify eventual production RLS policies. ESP32 firmware still lacks a
cycle identifier, so untagged responses after reconnection cannot be assigned
with certainty. Pending in-memory eggs do not survive a process crash. The
physical station lease is mocked in these database tests.
